# 音声データの作り方

このディレクトリの音声データ（`clip.raw` / `audio_rom.hex`）は、第三者の録音に由来するため
リポジトリには含めていません。手元の音源から各自で生成してください。

## 手順

### 1. 音源を切り出して生の16ビットPCMにする

```bash
ffmpeg -y -ss 80 -t 4 -i 元の音源.mp3 \
       -ac 1 -ar 48828 -f s16le -acodec pcm_s16le clip.raw
```

| 指定 | 意味 |
|---|---|
| `-ss 80 -t 4` | 開始80秒から4秒間を切り出す |
| `-ac 1` | 単音（左右同じ音を出すため） |
| `-ar 48828` | 標本化周波数。回路の fs = 12.5MHz÷256 = 48828.125Hz に合わせる |
| `-f s16le` | 16ビット符号付き、下位バイト先行の生データ |

MP3 でも WAV でも、ffmpeg が読める形式なら何でも構わない。

### 2. 読み込み用の16進テキストに変換

```bash
python raw2hex.py     # clip.raw → audio_rom.hex
```

実行すると標本数・再生時間・最大振幅・必要メモリが表示される。

**最大振幅が小さい場合は `raw2hex.py` の `GAIN` を上げる**。
16ビットの上限は 32767。最大振幅が 3000 程度なら `GAIN = 8.0` 前後にする。
小さいまま焼くと、鳴ってはいるが聞こえない状態になる。

### 3. ビルド

```bash
vivado -mode batch -source ../build_player.tcl
```

`i2s_player.v` の `ROM_LEN`（標本数）を、手順2で表示された標本数に合わせること。
4秒・48828Hz なら 195312。

## 容量の目安

| 長さ | 標本数 | 必要メモリ | 内蔵メモリ(5.1Mbit)に対して |
|---|---|---|---|
| 2秒 | 97656 | 1.56 Mbit | 余裕 |
| 4秒 | 195312 | 3.12 Mbit | 61%（実績あり） |
| 6秒 | 292968 | 4.69 Mbit | 92%（ほぼ上限） |

これより長くするには UltraRAM を使うか、PS 側の主記憶から読み出す仕組みが必要。
