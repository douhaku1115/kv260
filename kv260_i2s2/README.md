# kv260_i2s2 — Pmod I2S2 で I2S 送受信（段1〜段12）

KV260 の PL で I2S 送受信を組み、Pmod I2S2（CS5343 ADC / CS4344 DAC）で音を扱う。
- **段1**: PL 生成のサイン波を I2S 送信し、DAC からイヤホンで鳴らす（`i2s_tx.v` / `i2s2_tone`）
- **段2**: ADC 入力を PL でデジタル増幅して DAC へ戻すループバック（`i2s_loop.v` / `i2s2_loop`）
- **段3**: 位相アキュムレータでメロディ（きらきら星）を鳴らす（`i2s_melody.v`）
- **段4**: 内蔵メモリに焼いた録音を再生（`i2s_player.v`、上限6秒前後）
- **段5**: PS→PL AXI ストリーミングで曲まるごと再生（`i2s_stream_axi.v` / `audio_fifo.v`、早送り対応）
- **段6**: ステレオ化（FIFO32ビットで左右をまとめて流す）
- **段7**: PL でのリアルタイム音声加工（音量・エコー、`audio_fx.v`）
- **段8**: 再生中の音を FFT してパソコンにリアルタイムスペクトル表示（`spectrum_view.py`）
- **段9**: FFT を PL（FPGA）に載せる（自作512点FFT `fft512.v`、結果を AXI で読む）
- **段10**: エフェクト拡張（イコライザ・歪み、`audio_fx.v`）
- **段11**: DMA — PL が PS の DDR を自分で読み、CPU なしで再生（`axi_reader.v` / `dmaplay.c`）
- **段12**: SDR ラジオ — RTL-SDR で受けた FM 放送を鳴らす。PL 側の自作 FM 復調器
  （`fm_demod.v` / ステレオ版 `fm_demod_stereo.v`）と PS 側（`rtl_fm`）の二段構え。
  19kHz パイロットに PLL で追従してステレオ復調まで実装（実機でロック成功、
  ただし電界強度が足りずステレオは雑音になる）。音を良くする過程は全て実測で進めた

## 段1: 固定トーン再生

## 構成

```
Zynq PS (pl_clk0 100MHz) → Clocking Wizard (12.5MHz) → i2s_tx (Module Ref)
                                                          ├ MCLK 12.5MHz
                                                          ├ SCLK  3.125MHz (=MCLK/4, 64fs)
                                                          ├ LRCK  ≒48.8kHz (=MCLK/256, fs)
                                                          └ SDATA 標準I2S 16bit (NCO+64点サインLUT, ≒762Hz)
```

## ピンアサイン（KV260 carrier J2、Pmod I2S2 直挿し）

| 信号 | Pmod物理ピン | FPGA | 用途 |
|------|------|------|------|
| pmod_mclk | 1 | H12 | TX MCLK |
| pmod_lrck | 2 | E10 | TX LRCK |
| pmod_sclk | 3 | D10 | TX SCLK |
| pmod_sdin | 4 | C11 | TX SDATA(DACへ) |

（段2のRX用: B10/E12/D11/B11 = MCLK/LRCK/SCLK/SDOUT）

## 使い方

```bash
# プロジェクト生成
vivado -mode batch -source create_i2s2_project.tcl
# 合成→実装→ビットストリーム
vivado -mode batch -source build_bitstream.tcl
# 生成物: vivado/i2s2_tone.runs/impl_1/design_1_wrapper.bit
```

Vivado Hardware Manager で JTAG 書き込み後、Pmod I2S2 の DAC 出力ジャックにイヤホンを挿す。

## ハマりどころ：PLクロックがゲートOFF

JTAG で PL だけ書くと `pl0_ref` がゲートOFF（`clk_summary` で末尾 `N`）で MCLK が出ず**無音**になる。`/sys/class/fclk/` が無い環境では devmem で `PL0_REF_CTRL`(0xFF5E00C0) の CLKACT(bit24) を立てる：

```bash
sudo devmem 0xFF5E00C0           # 例: 0x00010A00 (bit24=0 → 無効)
sudo devmem 0xFF5E00C0 32 0x01010A00   # bit24=1 → 有効化
```

これでイヤホンからトーンが鳴る。恒久化するなら JTAG ではなく fpga_manager + デバイスツリーオーバーレイでロードし、クロックも自動有効化する。

## 段2: I2S ループバック（ADC→PL→DAC、デジタルゲイン付き）

ADC(CS5343) で受けた音を PL でデジタル増幅し、DAC(CS4344) へ戻す。クロック生成・TX 直列化・RX 並列化を 1 モジュール `i2s_loop.v` に統合し、単一のフレームカウンタで TX/RX のビット位置を揃える。

```
ADC(CS5343) ─SDOUT→ i2s_loop ┬ RX: SCLK立上りで16bit復元(L/R)
                              ├ GAIN倍(飽和付き, 既定32)
                              └ TX: 直列化 ─SDIN→ DAC(CS4344)
PL がマスタで ADC/DAC 両方へ MCLK12.5M / SCLK3.125M / LRCK≒48.8kHz を供給
```

### ピンアサイン（J2、DAC=上段 / ADC=下段）

| 信号 | Pmod物理ピン | FPGA | 用途 |
|------|------|------|------|
| dac_mclk/lrck/sclk/sdin | 1/2/3/4 | H12/E10/D10/C11 | DAC へ出力 |
| adc_mclk/lrck/sclk | 7/8/9 | B10/E12/D11 | ADC へクロック供給 |
| adc_sdout | 10 | B11 | ADC から入力 |

### 使い方

```bash
vivado -mode batch -source create_i2s2_loop_project.tcl
vivado -mode batch -source build_loop_bitstream.tcl
# 生成物: vivado_loop/i2s2_loop.runs/impl_1/design_1_wrapper.bit
```

書き込み後に段1と同じく PL クロックを有効化（`sudo devmem 0xFF5E00C0 32 0x01010A00`）。

### デジタル経路の検証（信号源が無い場合）

ライン入力(J5)に挿したプラグの金属に**濡れた指で触れる**と、体が拾う電源ハムが ADC に入る。これがゲイン倍されてスピーカーから「ブーン」と鳴れば、クロック・RX 取り込み・ループバック・DAC 出力まで全経路が正常と確認できる（音源やケーブル不要の切り分け）。

### 入力レベルの注意

Pmod I2S2 の ADC 入力(J5)は**ライン入力**。エレクトレットマイクはバイアス＋プリアンプが無いと信号を出せず、ゲインを上げてもハムだけが大きくなる。実用にはアンプ内蔵マイクモジュール(MAX9814 等)かライン級音源を使う。`GAIN` パラメータはライン級入力では `1` 前後に下げる（既定 32 は極小信号向けで、ライン級では飽和する）。

## 段3: メロディ再生（きらきら星）

固定トーンの NCO を拡張し、音階を切り替えてメロディを鳴らす（`i2s_melody.v` / `i2s2_melody`）。

### 固定トーンからの変更点

| | 段1（固定トーン） | 段3（メロディ） |
|---|---|---|
| 位相の進め方 | 1フレームごとに +1 | 24ビット位相アキュムレータに音ごとの増分を加算 |
| 周波数 | fs/64 = 762Hz 固定 | 任意（増分で決まる） |

```
PHASE_INC = 周波数 × 2^24 / fs        (fs = 48828.125Hz → 係数 343.597)
```

| 音 | 周波数 | PHASE_INC |
|---|---|---|
| ド C4 | 261.63Hz | 89893 |
| レ D4 | 293.66Hz | 100902 |
| ミ E4 | 329.63Hz | 113258 |
| ファ F4 | 349.23Hz | 119994 |
| ソ G4 | 392.00Hz | 134687 |
| ラ A4 | 440.00Hz | 151183 |
| シ B4 | 493.88Hz | 169696 |
| ド C5 | 523.25Hz | 179787 |

シーケンサは `NOTE_LEN`（12000標本 ≒ 0.25秒）ごとに次の音へ進み、16音でループする。

```bash
vivado -mode batch -source build_melody.tcl
# 生成物: vivado_melody/i2s2_melody.runs/impl_1/design_1_wrapper.bit
```

## 段4: 音声ファイル再生

合成ではなく、実際の録音をそのまま鳴らす。

```
音源(MP3等) --ffmpeg--> 生PCM --raw2hex.py--> audio_rom.hex --$readmemh--> 内蔵メモリ
```

音声データの作り方は [`audio/README.md`](audio/README.md) を参照。
音声データ自体は第三者の録音由来のためリポジトリには含めていない。

```bash
vivado -mode batch -source build_player.tcl
# 生成物: vivado_player/i2s2_player.runs/impl_1/design_1_wrapper.bit
```

### 容量

4秒（195312標本）で 3.12Mbit。内蔵メモリ 5.1Mbit の 61%。上限は6秒前後。

## 段5: 長時間再生（PS→PL AXI ストリーミング）

段4 は内蔵メモリに焼くため数秒が上限だった。段5 では PS(Linux) が音声標本を
AXI4-Lite 経由で PL の FIFO に流し込み、PL が 1 標本ずつ取り出して送出する。
内蔵メモリの容量制限が無くなり、**28分の曲でもそのまま鳴らせる**（`i2s_stream_axi.v` / `audio_fifo.v`）。

```
PS(Linux) ─M_AXI_HPM0_FPD─> AXI Interconnect ─AXI4-Lite─> i2s_stream_axi
   play song.raw                                            ├ FIFO(8192段)に積む
   (満杯を見て流量制御)                                       └ I2S 送信 ─SDIN→ DAC
```

### レジスタマップ（ベース 0xA000_0000）

| オフセット | 種別 | 内容 |
|------|------|------|
| 0x00 | W  | DATA   標本を1つ書き込む（下位16ビット） |
| 0x10 | R  | STATUS bit0:満杯 bit1:空 bit29..16:溜まっている数 |
| 0x20 | RW | CTRL   bit0:再生有効 |

**レジスタは 0x10 刻みに整列させる。** 0x10 境界に整列していないアドレスは
devmem/mmap の読み出しが 0 を返す（Zynq US+ の既知の挙動）。
0x04/0x08 に置いた STATUS/CTRL が常に 0 で読めず、原因究明に時間を要した。
動作確認用に 0x00 の読み出しで `0xDEADBEEF` を返すようにし、整列アドレスなら
正しく読めることを実機で確認して切り分けた。

### 使い方

```bash
# 音源(28分でも可)を生PCMに変換
ffmpeg -i 曲.mp3 -ac 1 -ar 48828 -f s16le -acodec pcm_s16le song.raw

# ビルド（生成物: vivado_stream/i2s2_stream.runs/impl_1/design_1_wrapper.bit）
vivado -mode batch -source build_stream.tcl

# KV260 側: 書き込み → クロック有効化 → 再生プログラムをコンパイルして実行
sudo fpgautil -b ~/stream.bit
sudo devmem 0xFF5E00C0 32 0x01010A00
gcc -O2 -o play play.c
sudo ./play song.raw
```

再生プログラム `sw/play.c` は STATUS の満杯ビットを見て流量を調整するので、
早送りにならず正しい速さで鳴る。再生中のキー操作：

- **f** … 10秒送り　**b** … 10秒戻し　**q** … 終了

## 段6: ステレオ化

段5 は左右同じ音（単音）だった。段6 では FIFO を32ビット幅にして1段に左右を
まとめて置き（`[31:16]=左, [15:0]=右`）、I2S 送出で LRCK の前半/後半に左右を振り分ける。

```bash
# 音源をステレオ(2ch)で変換する。以降は段5と同じ手順
ffmpeg -i 曲.mp3 -ac 2 -ar 48828 -f s16le -acodec pcm_s16le song.raw
```

`play.c` は左右2標本を `[31:16]=左, [15:0]=右` に詰めて1回で DATA に書く。
左右同じ値を書けばモノラルとしても使える。

## 段7: PL でのリアルタイム音声加工（音量・エコー）

FIFO と I2S 送出の間に信号処理モジュール `audio_fx.v` を挟み、PS から
`devmem` でリアルタイムに効き具合を変えられる。

```
FIFO → [音量 ×GAIN] → [+ エコー(遅延0.25秒×ECHO)] → 16bit飽和 → I2S
                              ↑___ BRAMディレイライン ___|
```

レジスタ追加（0x10刻みを維持）:

| オフセット | 種別 | 内容 |
|------|------|------|
| 0x30 | RW | GAIN 音量（64で等倍） |
| 0x40 | RW | ECHO エコー量（0=無効。大きいほど残響が長い） |

- **音量**: `in * GAIN >> 6`。左右それぞれに乗算
- **エコー**: BRAM ディレイライン（約0.25秒）から遅延音を読み、フィードバックで混ぜる（リバーブ風）

```bash
# 再生中に別端末（または止めてから）devmem で効かせる
sudo devmem 0xA0000040 32 0x80   # エコーを入れる
sudo devmem 0xA0000030 32 0x20   # 音量を半分に
```

## 段8: リアルタイムスペクトル表示

再生中の音を FFT して周波数成分をパソコンにグラフ表示する。

```
KV260(play.c)                          パソコン(spectrum_view.py)
  左chを8192点FFT ─ UDP:50007 ─> 1680ビン(0〜10kHz) ─> matplotlibで表示(dB軸)
```

- FFT は PS 側（`play.c`）で計算（反復 radix-2、8192点、分解能 ≒ 6Hz）
- 低域 1680 ビン（0〜約10kHz）の振幅を UDP でパソコンへ送る
- パソコンの `sw/spectrum_view.py`（matplotlib）が dB軸・塗りつぶし・ピークホールド・時間平滑化で描画

```bash
# パソコン側（matplotlib が必要）
pip install matplotlib numpy
python sw/spectrum_view.py

# KV260 側（第2引数にパソコンのIP。echo $SSH_CLIENT 等で確認）
sudo ./play song.raw <パソコンのIP>
```

FFT を PL に載せれば KV260 単体で完結できる（→ 段9）。

## 段9: PL で FFT（自作512点FFT）

段8 は FFT を PS（play.c）で計算していた。段9 では **PL（FPGA）に自作 FFT を載せる**。

```
再生中の左ch ─> PL: fft512(自作512点FFT) ─> 結果ダブルバッファ ─AXI─> PS が読む ─> パソコン表示
```

- `rtl/fft512.v`：DIT radix-2、逐次メモリベース（1バタフライ1クロック）、Q15固定小数点
- ツイドル係数は `rtl/gen_twiddle.py` で生成（`twiddle_{cos,sin}.hex`、256点）
- レジスタ追加（0x10刻み）：

| オフセット | 種別 | 内容 |
|------|------|------|
| 0x50 | W | FBIN 読み出すビン番号 |
| 0x60 | R | FRE そのビンの実部 |
| 0x70 | R | FIM そのビンの虚部 |

- PS は 256ビン分、FBIN を書いて FRE/FIM を読み、振幅を UDP でパソコンへ送る（512点なので分解能 ≒ 95Hz）

### ハマりどころ

- **配線混雑**：mem を分散RAM（reg配列）にしたため CLB 配線が混雑。ただし 12.5MHz 低速動作なので
  タイミングは達成（WNS ≒ 54ns）。BRAM 化すれば混雑は解消できる。
- **結果が読むたび変わる**：PL が FFT を連続で再計算しているため、PS が読む瞬間が計算中だと
  途中値（0を含む）を返す。→ **結果ダブルバッファ**（計算完了時に別バッファへコピー）で安定化。
  これをやる前は、実機で「約3000Hz（32ビン）周期の繰り返し」に見えていた。
- 切り分けは fft512 単体のシミュレーション（`sim/tb_fft512.v`）で「本体は正常」と確認してから
  実機側（結果の不安定さ）に絞った。

```bash
# 生成物はビルドに含まれる。ツイドルを作り直すなら:
python rtl/gen_twiddle.py
vivado -mode batch -source build_stream.tcl
```

## 段10: エフェクト拡張（イコライザ・歪み）

段7 の音量・エコーに加え、**低音／高音の調整**と**歪み（ディストーション）**を足す。

```
FIFO → 音量 → イコライザ(低音×BASS + 高音×TREBLE) → 歪み → エコー → I2S
```

### イコライザの作り

1次ローパス（1極 IIR）で低音成分を取り出し、残りを高音成分とする。

```verilog
lp += (in - lp) >> K        // K=5 で遮断 ≒ 48828/(2π·32) ≒ 243Hz
hi  = in - lp               // 高音 = 元の音 − 低音
out = (lp*BASS + hi*TREBLE) >> 6
```

### 歪みの作り

一定の高さで波形の頭を切る（クリップ）。切った分が高調波になり歪んだ音になる。
切る高さ = `32767 >> DIST[7:4]`。切ったあと同じだけ左シフトして音量を戻す。

### レジスタ（0x10刻み。FFT は 0x80〜0xA0 に移動）

| オフセット | 種別 | 内容 |
|------|------|------|
| 0x50 | RW | BASS 低音の強さ（64で等倍） |
| 0x60 | RW | TREBLE 高音の強さ（64で等倍） |
| 0x70 | RW | DIST 歪み（0=無効、大きいほど強い） |
| 0x80 | W | FBIN（PL FFT ビン番号） |
| 0x90 | R | FRE（PL FFT 実部） |
| 0xA0 | R | FIM（PL FFT 虚部） |

```bash
# 再生中に別端末から効かせる
sudo devmem 0xA0000050 32 0xFF   # 低音 最大
sudo devmem 0xA0000060 32 0x00   # 高音 ゼロ → こもった音
sudo devmem 0xA0000070 32 0x60   # 歪み 強め
# 元に戻す: BASS=0x40, TREBLE=0x40, DIST=0x00
```

**注意**: Verilog の関数（`clip16` / `clipdist`）は**使う前に定義**する位置に置くこと。

## 段11: DMA — PL が PS の DDR を自分で読む（段階1 完了）

段5〜10 では **PS が AXI4-Lite で 1 標本ずつ書き込んで**いた（CPU が働き続ける）。
段11 では逆に、**PL が主人になって PS の DDR を直接読む**。PS は「どこから何バイト
読むか」を教えるだけ。

```
PS DDR ←─ S_AXI_HP0 ←─ 自作AXI4読み出しマスタ(axi_reader.v) ─→ (段階2で FIFO へ)
                              ↑ PS はレジスタで指示するだけ
```

### 自作 AXI4 読み出しマスタ（`rtl/axi_reader.v`）

AXI DMA IP を使わず自作した。読み出しのみなので構造は単純：

1. **AR チャネル**で「このアドレスから N 個読みたい」と要求
2. **R チャネル**でデータが順に返る。最後に `RLAST=1`

1 回の要求でまとめて連続転送する（**バースト転送**）。1 標本ずつやり取りする
AXI4-Lite より遥かに効率が良い。ここでは 1 転送 = 64bit、16 転送 = 128 バイトを
1 バーストとした。

### レジスタ

| オフセット | 種別 | 内容 |
|------|------|------|
| 0xB0 | RW | DMA_ADDR 読み出し開始アドレス（DDR 物理アドレス） |
| 0xC0 | RW | DMA_LEN 読み出す長さ（バイト） |
| 0xD0 | W | DMA_CTRL bit0 に 1 を書くと開始 |
| 0xE0 | R | DMA_STAT bit0=busy, bit1=done, [31:8]=読んだバイト数 |
| 0xF0 | R | DMA_DATA 最後に読めたデータ（確認用） |

### 動作確認

```bash
# DDR に目印を書く
sudo devmem 0x10000000 32 0x11223344

# PL に読ませる
sudo devmem 0xA00000B0 32 0x10000000   # 開始アドレス
sudo devmem 0xA00000C0 32 8            # 8バイト読む
sudo devmem 0xA00000D0 32 1            # 開始
sudo devmem 0xA00000E0 32              # → 0x00008002 (done, 読んだバイト数)
sudo devmem 0xA00000F0 32              # → 0x11223344 (読めたデータ)
```

### ハマりどころ

- **PS 側で HP ポートを有効にする**: `CONFIG.PSU__USE__S_AXI_GP2 {1}`
  （S_AXI_GP2 = S_AXI_HP0_FPD）。HPM（制御用・細い）とは別の、データ用の広帯域ポート。
- **クロック周波数の一致**: `FREQ_HZ does not match` で `validate_bd_design` が失敗する。
  自作モジュールの M_AXI は既定で 100MHz と見なされる。**12500000 と書いても駄目**で、
  clk_wiz が実際に出す値（例 12501995）に合わせる必要がある。TCL では
  `get_property CONFIG.FREQ_HZ [get_bd_pins clk/clk_out1]` で実値を取って設定している。
- **DMA から見た DDR のアドレス割り当てが要る**: `assign_bd_address` で
  `ps/SAXIGP2/HP0_DDR_LOW` を自作マスタのアドレス空間に割り当てないと読めない。
- **書き込みチャネルもダミーで用意する**: 読み出し専用でも AW/W/B の端子が無いと
  Vivado が AXI4 インターフェースとして認識しない。0 に固定して繋いでおく。

### 段階2: CPU を使わない再生（完了）

読んだデータを FIFO へ流し込み、**CPU を一切使わずに音を鳴らす**。
再生プログラム `sw/dmaplay.c` は音声を DDR に転送して DMA を起動したら**すぐ終了する**が、
音は鳴り続ける。これが「PL が自律的に動く」ことの証拠。

```
DDR(0x60000000) ─HP0─> axi_reader ─64bit─> FIFO ─> audio_fx ─> I2S ─> DAC
                            ↑ 満杯なら out_ready を下げて待つ（PL内で完結、CPU不要）
```

#### 物理連続メモリの確保（`mem=` で予約）

Linux は通常メモリが物理的に断片化しているため、そのままでは PL に「ここから連続で
読め」と教えられない。**起動引数で Linux の使用領域を制限し、その上を PL 専用にする。**

SD カードのブート領域にある `uEnv.txt` を編集する（`/run/media/boot-mmcblk1p1/uEnv.txt`）:

```
bootargs=... cma=256M mem=1536M
```

| 領域 | 用途 |
|---|---|
| 0x00000000〜0x5FFFFFFF (1.5GB) | Linux が使う |
| **0x60000000〜0x7FEFFFFF (約511MB)** | **Linux 管理外。PL 専用に自由に使える** |

再起動後 `/proc/iomem` の System RAM が `0x00000000-0x5fffffff` に縮めば成功。
音声に限らず、映像フレームバッファや PL の作業領域としても使える汎用の置き場になる。

**注意**: 予約前に 0x10000000 などへ書くと、Linux が使用中のメモリを壊す恐れがある。

#### 追加した仕組み

- **流量制御**: FIFO が満杯なら `out_ready` を下げて DMA を待たせる。PL 内の配線1本で
  完結し、CPU は関与しない（段5〜10 では CPU が STATUS を読んで待っていた）
- **64bit → FIFO**: 1 転送(64bit) は左右2組ぶん。2 クロックに分けて FIFO へ入れる
- **繰り返し再生**: `DMA_CTRL` bit1 を立てると、読み終わりに自動で先頭へ戻る

```bash
# パソコン側: ステレオ生PCMを用意
ffmpeg -i 曲.mp3 -ac 2 -ar 48828 -f s16le -acodec pcm_s16le song.raw

# KV260 側
gcc -o dmaplay dmaplay.c
sudo ./dmaplay song.raw     # 転送して再生開始。すぐ終了するが鳴り続ける
sudo ./dmaplay --stop       # 停止
```

## 段12: SDR ラジオ — PL で FM 復調する

RTL-SDR（USB受信機）で受けた電波を、**PL に載せた自作 FM 復調器**で音声にする。
段11 で作った DMA がそのまま活きる。

```
電波 → RTL-SDR(IQ) → PS が DDR へ → PL: fm_demod → イコライザ → I2S → イヤホン
```

### 二段構え

| | 復調する場所 |
|---|---|
| `sw/radio.c` | PS（`rtl_fm`） |
| `sw/fmradio.c` | **PL（自作 `fm_demod.v`）** |

### FM 復調の原理（`rtl/fm_demod.v`）

FM は「周波数の変化」に音が乗っている。周波数＝位相の進む速さなので、
**1標本ごとの位相差**を取れば音になる。

```verilog
// 音 ∝ arg( z[n] × conj(z[n-1]) )
// 複素数の掛け算を展開した虚部（sin成分）を使う
wire signed [31:0] cross = prev_i * in_q - prev_q * in_i;
```

### ★振幅の正規化（これが無いと雑音になる）

`cross` には **A²（振幅の2乗）が掛かったまま**残る。FM 放送の振幅は本来一定だが、
実際の受信では強度が常に揺れる。その揺れが A² としてそのまま音量変動＝雑音になる。

そこで `mag2 = I² + Q²`（= A²）で割って `sin(Δφ)` だけを取り出す。
除算器は重いので**シフトで近似**する。

```verilog
wire [5:0] k  = msb_pos(mag2);              // mag2 の最上位ビット位置 → mag2 ≒ 2^k
wire [5:0] sh = (k > 15) ? (k - 15) : 0;    // 15bit の小数精度を残す
wire signed [17:0] norm = cross >>> sh;     // ≒ sin(Δφ) × 32768
```

`|cross| ≦ mag2` なので結果は必ず ±32768 に収まる。誤差は最大2倍（6dB）だが、
正規化なし（振幅変動がそのまま乗る）に比べればはるかに良い。

**シミュレーションでの検証**（`sim/tb_fm_demod_amp.v`）:
同じ変調信号を振幅を変えて入れ、出力の大きさを比べた。

| | 振幅8000 | 振幅1000 | 比 |
|---|---|---|---|
| 正規化なし | 8604 | 135 | **63.7**（振幅²がそのまま出る） |
| 正規化あり | 28973 | 28945 | **1.00** |

### ★IQ のレートは下げてはいけない（sin 近似の条件）

上の式は `sin(Δφ) ≒ Δφ` と近似している。この近似には条件がある。

```
Δφ = 2π × 75000 / fs        （75kHz は FM 放送の最大周波数偏移）
```

| IQ レート | Δφ（最大偏移時） | |
|---|---|---|
| 976560Hz | 0.48 rad = 27.6° | 近似が成立する |
| 244140Hz | **1.93 rad = 110.6°** | **破綻する** |

90°を超えると sin は減少に転じるため、**偏移が大きいほど出力が小さくなる**という
逆転が起き、強く歪む。`rtl_fm` が 244140Hz でも平気なのは、近似ではなく `atan2` を
使っているからで、こちらは真似できない。

一度「雑音を減らすため」に 244140Hz へ下げたが、これは誤りだった。
目的は**帯域を絞ること**であって**レートを下げること**ではない。

### 復調の「前」の帯域制限（間引かずにフィルタだけ掛ける）

976560Hz で受けると帯域は ±488kHz ある。FM 放送が占めるのは ±100kHz 程度なので、
残りは全部ただの雑音として復調器に入ってくる。

そこで **レートを保ったまま帯域だけ絞る**。I・Q それぞれに 4点移動平均を3段かける。
加算とシフトだけで済み、乗算器は要らない。

```verilog
wire signed [15:0] ia_out = (ia0 + ia1 + ia2 + ia3) >>> 2;   // 1段目
wire signed [15:0] ib_out = (ib0 + ib1 + ib2 + ib3) >>> 2;   // 2段目
wire signed [15:0] flt_i  = (ic0 + ic1 + ic2 + ic3) >>> 2;   // 3段目
```

4点移動平均の振幅応答は `|sin(4πf/fs) / (4·sin(πf/fs))|` で、**fs/4 = 244140Hz に
ヌル点**を持つ。3段かけるとその3乗になる。

**シミュレーションでの検証**（`sim/tb_fm_demod_bpf.v`）:
振幅一定の複素正弦波を入れ、フィルタ通過後の振幅を測った。

| 周波数 | 実測 | 理論値 |
|---|---|---|
| 100kHz | -7.2dB | -7.2dB |
| **122kHz**（FM放送の端） | **-11.1dB** | -11.1dB |
| 244kHz | **振幅 0**（ヌル点） | — |
| 300kHz | -41.7dB | -42.0dB |
| 400kHz | -37.5dB | -37.6dB |

放送帯域を残したまま、帯域外を 40dB 前後落とせている。

### 間引き（デシメーション）

IQ は毎秒 976560 組、音声は 48828 標本。**20分の1に間引く**。
単純な移動平均（1次CIC）では折り返し雑音が落ちきらないので、**3次CIC**を使う。
積分3段 → 間引き → 差分3段、という構成で、乗算器を使わずに急峻な特性が得られる。

**シミュレーションでの検証**（`sim/tb_fm_demod_alias.v`）:
ステレオ副搬送波の位置（38kHz）を入れ、音声帯域へどれだけ漏れるかを測った。

| | 38kHz の漏れ |
|---|---|
| 1次CIC（単純な移動平均） | -11.5dB |
| **3次CIC** | **-42.3dB** |

#### 出力のスケーリングは DECIM から自動で決める

CIC の利得は `DECIM³` になるので割り戻す必要がある。ここを固定シフトで書くと
間引き比を変えたときに合わなくなる（実際 `>>>13`＝DECIM=20 専用のまま
DECIM=5 にして **64倍ずれた**）。

```verilog
localparam integer CIC_GAIN  = DECIM * DECIM * DECIM;
localparam integer CIC_SHIFT = $clog2(CIC_GAIN);   // 20→13、5→7
wire signed [31:0] cic_scaled = d3 >>> CIC_SHIFT;
```

### 出力段のフィルタ（PS 側と同じものを PL に載せる）

PL 内蔵の FFT で PS 復調と PL 復調を比べたところ、**PS 側が 4.6dB 静か**だった。
原因は、PS 側（`radio.c`）が持っている音声帯域のフィルタが PL 側に無かったこと。

| | 30Hz 高域通過 | デエンファシス | 15kHz 低域通過 |
|---|---|---|---|
| `radio.c`（PS） | あり | あり | あり |
| `fm_demod.v`（PL、以前） | なし | あり | **なし** |

CIC は間引きのためのフィルタなので、音声帯域のすぐ上を落とす能力は無い（計算値で
19kHz が -7dB、20kHz 以上の折り返し成分が -12dB 程度）。そこで同じ2つを PL に載せた。

**30Hz 高域通過**（1次、直流とうねりを落とす）:

```verilog
localparam signed [17:0] HP_A = 18'sd65283;      // a×65536、a = exp(-2π·30/48828)
wire signed [31:0] hp_next = pre_hp - hp_x1 + (hp_y1 * HP_A >>> 16);
```

**15kHz 低域通過**（63タップ FIR、19kHz パイロットを落とす）。係数は `rtl/fir15k.hex`。

### FIR は乗算器1個を使い回す（＋流量制御）

63タップぶんの乗算器を並べるのは無駄なので、**1個を 63 クロック使い回す**。
出力は 48828Hz（＝2048 クロックに1回）なので通常は余裕で間に合う。

ただし DMA が IQ を連続で送ってくると間引き点の間隔が 20 クロックまで詰まり、
計算が終わらないうちに次が来る。そこで **計算中は `in_ready` を下げて DMA を待たせる**。

```verilog
// fm_demod.v
assign in_ready = ~fir_busy;

// i2s_stream_axi.v
wire dma_ready = !dma_half & !fifo_full & (!reg_fm_mode | fm_in_ready);
```

この流量制御を入れると、**テストベンチ側も `in_ready` に従わせる必要がある**。
無視して毎クロック送ると積和がやり直しになり続け、出力が一切出なくなる。

```verilog
in_valid <= 1'b0;
@(posedge clk);
while (!in_ready) @(posedge clk);      // ← これが要る
in_i <= ...; in_q <= ...; in_valid <= 1'b1;
@(posedge clk);
```

### 雑音とプチプチを潰す（実測にもとづく）

「聞こえる」ところまでは簡単だが、そこから音を良くするのは**測らないと進まない**。
推測で直そうとして何度も外したので、以下は全て実測で確かめたもの。

#### 切り分けの方法

まず**原因がどちら側にあるか**を確定させる。`sw/playraw.c` は録音済みのファイルを
FIFO へ流すだけのプログラムで、USB・rtl_fm・パイプというリアルタイム要因を全て外せる。

| | ファイル再生 | リアルタイム受信 | 結論 |
|---|---|---|---|
| プチプチ | 出ない | 出る | **供給側**の問題 |
| 雑音 | 出る | 出る | **受信・復調**の問題 |

#### プチプチの原因（2つとも `sw/radio.c` 側）

1. **スペクトル送信が常に走っていた**
   `send_spectrum()` の「送り先があるか」の判定が関数の最後にあり、
   パソコンの IP を指定していなくても毎秒 1024 回のレジスタ読み書きと
   256 回の平方根計算が走っていた。その間 FIFO への供給が止まる。
   → 冒頭で `if (g_sock < 0) return;` する。

2. **FIFO の状態を毎標本読んでいた**
   48828 回/秒 の AXI 読みは、それ自体が rtl_fm からの読み取りを圧迫する。
   → STATUS の `bit[29:16]` にある残量を一度読み、「あと何個書けるか」を
   覚えておいて、その分は状態を読まずに書く（`fifo_put()`）。

なお FIFO は 8192 段（約0.17秒）あり、残量を実測すると 2900〜5300 の間で
振動していた。**空にはなっていない**ので、単純な供給不足ではなかった。

#### 雑音の内訳（`sw/check_raw.py` と FFT で測った）

録音した音声の周波数分布を見ると、正体がはっきり分かる。

| 帯域 | 実測 | 正体 |
|---|---|---|
| 0〜300Hz | 全パワーのほぼ全部 | 直流とドリフト（ゴロゴロ音） |
| 18.5〜19.5kHz | 周囲より 12dB 高い | ステレオのパイロット信号 |
| 全帯域 | 信号との差 33〜40dB | 受信そのものの雑音 |

対策として `sw/radio.c` に2つのフィルタを入れた（処理順は 高域通過 → デエンファシス → 低域通過）。

- **30Hz 高域通過**（1次）… 直流と超低域を落とす
- **15kHz 低域通過**（63タップ FIR）… 19kHz パイロットを落とす
  実測の減衰量: 13kHz 0dB / 15kHz -6dB / 17kHz -60dB / **19kHz -56dB**

#### rtl_fm のオプションは実測で決める

87.2MHz を 20 秒ずつ録音し、**音声の無い 20〜24kHz の絶対パワー**（＝雑音床）で比較した。
「雑音/音声」の比で測ると放送内容（音楽か喋りか）に左右されるので使えない。

| 設定 | 雑音床 | 信号との差 |
|---|---|---|
| **`-g 30`** | **88.0dB** | **39.8dB** ← 最良 |
| `-g 20` | 88.5dB | 38.7dB |
| `-g 40` | 87.1dB | 36.2dB |
| ゲイン自動（既定） | 90.2dB | 33.6dB |
| `-g 49`（最大） | 92.9dB | 31.8dB |
| `-F 9` を付けた3通り | 91.8〜94.5dB | 33〜35dB |

- **ゲインは自動にしない**。`-g 30` 固定で約 5dB 改善する。最大ゲインは最悪。
- **`-F 9`（高品質FIR）は使わない**。名前に反して雑音が 3〜6dB 増えた。
- **`-s` は 244140（48828×5）**。195312 に狭めると逆に悪化した（93.4dB）。
  なお整数比であることは必須で、`-s 200k -r 48828` は 4.096 倍になり歪む。

#### ここから先はソフトでは伸びない

掃引すると、舞鶴では 87.2MHz が雑音床より **21.5dB** で唯一まともに受かる局だった
（84.14MHz は 8.3dB しかない）。FM は信号が雑音より約 20dB 以上強くないと
雑音抑圧が働かない（しきい値効果）ため、21.5dB は崖のふちに乗っている状態になる。

付属の短い棒アンテナを水平にして窓際へ移しても、**信号が 1.4dB 上がると同時に
雑音床も 1.7dB 上がり、差は 21.5dB → 21.3dB で変わらなかった**。
つまり雑音は外来で、アンテナの感度を上げても信号と一緒に増える。
指向性アンテナか、雑音源（KV260 本体そのものの疑いが濃い）から離すしかない。

### ステレオ復調（`fm_demod_stereo.v` / `stereo_pll.v`）

モノラル版の後段を 2 本に増やしてステレオ化した。旧 `fm_demod.v` は動作実績が
あるのでそのまま残してある。

```
IQ → 帯域制限 → 位相差 → 振幅で正規化 → MPX
                                        │
                 ┌──────────────────────┤
                 │                      │
                 │              19kHz PLL → 38kHz
                 │                      │
                 │            ×2cos(2ωt)（周波数変換）
                 │                      │
              [S=L+R]                [D=L−R]
                 │                      │
           3次CIC 1/20            3次CIC 1/20
           30Hz 高域通過           30Hz 高域通過
           デエンファシス50µs      デエンファシス50µs
           15kHz FIR              15kHz FIR
                 │                      │
                 └──── L=S+D / R=S−D ───┘
```

#### なぜ PLL が要るのか

L−R は 38kHz を中心に置かれているが、**38kHz の搬送波そのものは送信されていない**
（DSB-SC＝抑圧搬送波。電力の節約とモノラル受信機との互換のため）。代わりに半分の
19kHz が小さく送られていて、これがパイロット信号。受信側はこれに PLL で追従し、
2 倍して 38kHz を作る。

位相がずれると分離度が落ちる。**位相誤差 θ に対する分離度の上限は −20·log10(tanθ)**
なので、1度ずれると 35dB、6度ずれると 20dB までしか分離できない。

#### シミュレーション（`sim/tb_fm_stereo.v`、5項目すべて PASS）

| 条件 | 結果 |
|---|---|
| ステレオ素材（L のみ 1kHz） | **分離度 42.9dB** |
| モノラル素材（L=R） | L/R 差 −0.10dB |
| パイロット無しの放送 | ロックせず、L と R が完全一致 |

#### 実機の結果 — 回路は正しいが電波が足りない

| 項目 | 実測 |
|---|---|
| パイロット強度 | 709〜737（しきい値 400） |
| 位相誤差 | **0.00〜0.97 度**（分離度の上限 29〜99dB） |
| D/S（L−R ÷ L+R） | 0.070〜0.284 |

PLL は正確にロックしている。しかし **L−R を単独で聞くとほとんど雑音**で、
強制モノラル（`0x4007`）のほうが静かに聞こえる。

理由は原理的なもの。FM の雑音は**周波数の2乗で増える**（三角雑音）。L−R は 38kHz を
中心に置かれているので、0〜15kHz にある L+R よりはるかに雑音を拾う。**ステレオ受信は
モノラルより 20dB 以上 SN が悪い。** 舞鶴で最も強い 87.2MHz でも雑音床より 21.5dB
しかないので、ステレオを成立させる余裕が無い。

市販のラジオが電波の弱いときに自動でモノラルへ切り替える（ステレオブレンド）のは
これが理由で、こちらも同じ対策が要る。

#### 動かし方

```bash
sudo ./fmradio 87.2M
sudo devmem 0xA00000D0 32 0x400F     # ステレオ許可（bit3=1）
sudo devmem 0xA00000D0 32 0x4007     # 強制モノラル
sudo devmem 0xA00000D0 32 0xFF1F     # 診断: L−R だけを大きめの音量で聞く
```

`0x100` に 19kHz パイロットの強さ、`0xE0` の bit2 にロック状態が出る。

### 測定ツール `sw/fftmeter.c` — 復調方式を同じ土俵で比べる

段9 で PL に載せた FFT は **FIFO の出力（＝実際に鳴っている音）** を見ている。
つまり PS が復調しようが PL が復調しようが、同じレジスタから同じ条件で
出力スペクトルを読める。

```bash
sudo nohup ./radio 87.2M < /dev/null > /dev/null 2>&1 &   # PS 復調
sudo ./fftmeter 20
```

音声（300Hz〜3kHz）と雑音床（20k〜24kHz）を平均して比を出す。
**耳で「こちらが良い気がする」と判断すると外す**ので、必ずこれで測ってから直すこと。

> `sudo` をバックグラウンドで動かすとパスワード入力で停止する（SIGTTIN）。
> 先に `sudo -v` でパスワードを通し、`< /dev/null` で標準入力を切ること。

### PL 復調版の経緯（一度間違えて戻した）

`sw/fmradio.c`（PL で復調する版）は、当初 `radio.c` より雑音が多かった。
「雑音を取り込みすぎている」と考えて IQ を 976560Hz → 244140Hz に下げたが、
これは**誤り**だった。sin 近似が破綻して逆に歪む（上記）。

正しい対策は「レートを下げる」ではなく「レートを保ったまま帯域を絞る」で、
`fm_demod.v` に 4点移動平均×3段を追加して解決した。あわせて、固定シフトだった
CIC のスケーリングを `$clog2(DECIM³)` による自動計算に直した。

### ハマりどころ

- **デエンファシスの時定数**：日本は 50µs だが `rtl_fm -E deemp` は 75µs（米国仕様）。
  高音が落ちすぎてこもる。自前で 50µs を掛けること（`α×256 = 86`）。
- **`rtl_sdr` の出力は符号なし8ビット**（中心128）。PL の復調器に渡す前に
  `(値-128)<<6` で符号付き16ビットに変換する。
- **`rtl_sdr` には DC スパイク対策が無い**。`rtl_fm` は指定周波数から 316kHz
  ずらして同調し内部で戻している（オフセット同調）が、`rtl_sdr` はしない。
  ただし実測では I=-40, Q=-39（振幅 8128 に対し 0.5%）で、音への影響は無かった。
- **サンプリング速度を変えると復調出力の大きさも変わる**。位相差は
  `Δφ = 2π × 75000 / fs` なので、976560 → 244140 にすると 4 倍になり音が割れる。
  音量レジスタ（`0xA0000030`）で下げること。
- 受信機の権限：`sudo` が要る（`usb_open error -3` は権限不足）。
  `usb_claim_interface error -6` は「既に他のプログラムが使用中」。
  `radio.c` は内部で `rtl_fm` を起動するので、外から `rtl_fm | ...` と繋ぐと衝突する。
- **RTL-SDR は偽の信号（スプリアス）を出す**。掃引で 120.000 / 125.000 /
  432.000MHz といった**キリのいい整数値**に山が出たら疑うこと。
  2分間 5秒おきに測ると、本物の交信はレベルが上下するが、スプリアスは
  変動幅 0.2dB で一定だった。

## ★書き込みは fpgautil を使う（重要）

**Vivado の JTAG 書き込みでは PL クロックが供給されず、無音になる。**
JTAG は PL のみを書き換え、PS 側の設定（クロック出力）を変更しないため。

```bash
# パソコン側（末尾の :~/ を忘れない。無いとローカルコピーになる）
scp -O <bitファイル> petalinux@<KV260のIP>:~/player.bit

# KV260 側
sudo fpgautil -b ~/player.bit              # ← JTAG ではなくこれ
sudo devmem 0xFF5E00C0 32 0x01010A00       # PLクロック有効化
```

止めるときは PL クロックを切る:

```bash
sudo devmem 0xFF5E00C0 32 0x00010A00
```
