## はじめに

Xilinx Kria KV260 の PL（FPGA）から Pmod I2S2 で音を鳴らす記事の続きです。

- 段8（[前回](https://zenn.dev/)）では、再生中の音を **PS（play.c）で FFT** して
  パソコンにスペクトル表示しました。
- 段9 では、その FFT を **PL（FPGA）に載せます**。自作の512点 FFT を Verilog で書き、
  結果を AXI 経由で PS が読んでパソコンに表示します。

「FPGA で FFT」を IP に頼らず自作したい、という趣旨です。

## 自作512点 FFT（fft512.v）

方式は **DIT radix-2、逐次メモリベース**にしました。バタフライ演算器を1つだけ持ち、
メモリ上でその場（in-place）計算を繰り返します。1バタフライ1クロックで、
総クロックは 512（ロード）+ 256×9（計算）≒ 3000。12.5MHz で約0.24ms。
512点をためるのに 512/48828 ≒ 10.5ms かかるので、計算は十分間に合います。

固定小数点は Q15（16bit）。各段で `>>1` してオーバーフローを抑えます。
ツイドル係数 W_N^k = cos(2πk/N) − i·sin(2πk/N) は Python で生成して`$readmemh`で読みます。

```verilog
// 複素バタフライ（Q15）: t = W * v,  W = cos - i sin
wire signed [32:0] mr = cw * vr + sw * vi;   // tr*2^15
wire signed [32:0] mi = cw * vi - sw * vr;
wire signed [15:0] tr = mr >>> 15;
wire signed [15:0] ti = mi >>> 15;
wire signed [15:0] sum_r = (ur + tr) >>> 1;  // 各段 >>1 でスケール
wire signed [15:0] dif_r = (ur - tr) >>> 1;
```

入力の並べ替えは DIT なのでビットリバース。状態機械は
`IDLE → LOAD → COMPUTE → (COPY) → DONE` です（COPY は後述）。

### まず単体でシミュレーション

いきなり実機に載せる前に、3000Hz の正弦波を入れてピークが正しいビンに出るか
`sim/tb_fft512.v` で確認しました。

```
入力3000Hz -> ピークビン=31, 周波数=2956Hz  PASS
```

分解能は 48828/512 ≒ 95Hz なので、3000Hz はビン31（2956Hz）。正しく出ました。

## AXI で結果を読む

PL の FFT 結果を PS が読むためのレジスタを足しました（0x10 刻みに整列）。

| オフセット | 種別 | 内容 |
|------|------|------|
| 0x50 | W | FBIN 読み出すビン番号 |
| 0x60 | R | FRE 実部 |
| 0x70 | R | FIM 虚部 |

PS は「FBIN にビン番号を書く → FRE/FIM を読む」を256回繰り返し、振幅を計算して
UDP でパソコンに送ります。再生音は FIFO から左chを取り出して FFT に供給します。

## ハマりどころ

### 配線が混雑する

`mem` を reg 配列（分散RAM）で作ったため、512×16bit×2 が LUT に展開され、さらに
2ポート同時読みの大きなマルチプレクサになって **CLB 配線が混雑**しました。
ただし 12.5MHz 低速動作なので、混雑してもタイミングは達成（WNS ≒ 54ns）。
本気で小さくするなら mem を BRAM 化すべきですが、まず動かすことを優先しました。

### 結果が読むたびに変わる（32ビン周期の繰り返し）

実機でグラフを見ると、**約3000Hz（32ビン）周期で同じ波形が繰り返す**という
おかしな表示になりました。

原因の切り分けに、まず `fft512` 単体のシミュレーションで全ビンを見ました。

```
bin31 (2956Hz) mag^2=12016777   ← 突出
bin63 (6008Hz) mag^2=1585
bin95 (9060Hz) mag^2=340   ...  減衰していく（繰り返していない）
```

**fft512 本体は正常**でした。つまり原因は実機側。devmem で FFT レジスタを読むと、
同じビンでも読むたびに値が変わる（0 だったり非0だったり）ことが分かりました。

真因は、**PL が FFT を連続で再計算していて、PS が読む瞬間が計算中だと途中値を返す**
ことでした。読むタイミングによって別の計算世代が混ざり、結果として周期的な繰り返しに
見えていたのです。

対策は **結果ダブルバッファ**。計算完了時（COPY 状態）に結果を別バッファへコピーし、
PS はそのバッファを読むようにしました。

```verilog
COPY: begin
    out_re[copy_cnt] <= mre[copy_cnt];   // 片側256ビンをバッファへ
    out_im[copy_cnt] <= mim[copy_cnt];
    if (copy_cnt == 8'd255) state <= DONE;
    else copy_cnt <= copy_cnt + 1'b1;
end
```

これで結果が安定し、32ビン周期の繰り返しは消えて、正しいスペクトルが表示されました。

## まとめ

- IP に頼らず、DIT radix-2 の512点 FFT を Verilog で自作して PL に載せた。
- **まず単体シミュレーションで本体の正しさを確認**してから実機に載せると、
  実機で問題が出ても切り分けが速い（今回は「本体は正常→実機側」と即断できた）。
- **PL で連続計算した結果を PS が読むときは、ダブルバッファで安定化する**。
  さもないと計算中の途中値を読み、周期的な繰り返しなど不可解な表示になる。
- 分散RAM は配線が混雑する。低速なら通るが、規模を詰めるなら BRAM 化する。
