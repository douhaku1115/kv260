## はじめに

Xilinx Kria KV260 の PL（FPGA）で音を扱う記事の続きです。

段11 までで、PL が PS の DDR を自分で読んで CPU なしに音を鳴らせるようになりました。
今回は入力を**電波**にします。RTL-SDR（USB の SDR 受信機、2000円程度）で FM 放送を受け、
**PL に載せた自作 FM 復調器**で音声にして Pmod I2S2 から鳴らします。

```
電波 → RTL-SDR(IQ) → PS が DDR へ → PL: fm_demod → イコライザ → I2S → イヤホン
```

比較用に、PS 側の `rtl_fm` に復調させる版も作りました。

| | 復調する場所 |
|---|---|
| `sw/radio.c` | PS（`rtl_fm`） |
| `sw/fmradio.c` | **PL（自作 `fm_demod.v`）** |

結論を先に書くと、**音を鳴らすところまでは早かったが、そこから音を良くするのに
ずっと苦労しました**。そして苦労した部分のほとんどは「推測でいじって外す」の繰り返しで、
測ってからは一直線でした。この記事は後半が本題です。

## FM 復調の原理

FM は「周波数の変化」に音が乗っています。周波数とは位相の進む速さなので、
**1標本ごとの位相の差**を取れば音になります。

RTL-SDR が出すのは IQ（複素数）です。連続する2点の位相差は、複素共役の積の偏角です。

```
音 ∝ arg( z[n] × conj(z[n-1]) )
```

偏角を求めるには arctan が要りますが、位相差が小さければ `sin(Δφ) ≒ Δφ` と近似できます。
そして `sin` 成分は、複素数の掛け算を展開した**虚部**そのものです。

```verilog
// cross = I[n-1]·Q[n] − Q[n-1]·I[n] = A²·sin(Δφ)
wire signed [31:0] cross = prev_i * in_q - prev_q * in_i;
```

掛け算2つと引き算1つで復調できます。arctan もテーブルも要りません。

## ★振幅の正規化（これが無いと雑音になる）

上の式には **A²（振幅の2乗）が掛かったまま**残っています。

FM の振幅は本来一定なので無視できそうですが、実際の受信では強度が常に揺れます。
建物の陰、人の動き、フェージング。その揺れが A² としてそのまま音量変動、つまり雑音になります。

そこで `mag2 = I² + Q²`（= A²）で割ります。ただし FPGA で除算器は重いので、
**逆数のテーブルとシフト**で近似します。

```verilog
wire [5:0] k    = msb_pos(mag2);              // mag2 の最上位ビット位置
wire [5:0] ksh  = (k > 3) ? (k - 3) : 0;
wire [3:0] top4 = mag2[ksh +: 4];             // 上位4ビットだけ見る

// 32768 / top4 の表（top4 は 8〜15 の範囲に正規化されている）
//   8→4096  9→3641  10→3277  11→2979  12→2731  13→2521  14→2341  15→2185
wire signed [44:0] cross_r = cross * recip;
wire signed [44:0] norm45  = cross_r >>> ksh;
```

要点は、`mag2` を「2の冪 × 上位4ビット」に分解し、2の冪の部分はシフトで、
残りの4ビットだけを 8 エントリのテーブルで処理することです。

### 効果をシミュレーションで確かめる

同じ変調信号を、振幅だけ変えて入れます。

| | 振幅8000 | 振幅1000 | 比 |
|---|---|---|---|
| 正規化なし | 8604 | 135 | **63.7**（振幅²がそのまま出る） |
| 正規化あり | 28973 | 28945 | **1.00** |

振幅が 8分の1 になると、正規化なしでは出力が 64分の1（＝8²）になります。
教科書通りの結果ですが、実際に測ると納得感が違います。

## 間引きは3次CICで

IQ は毎秒 244140 組、音声は 48828 標本なので 5分の1に間引きます。

単純な移動平均（1次CIC）で済ませようとすると、折り返し雑音が落ちきりません。
FM 放送の信号には音声（〜15kHz）のほかに **19kHz のパイロット信号**と
**23〜53kHz のステレオ副搬送波**が乗っていて、これらが音声帯域に折り返してきます。

そこで **3次CIC**（積分3段 → 間引き → 差分3段）にしました。乗算器を使わずに
急峻な特性が得られるのが CIC の利点です。

```verilog
// 積分器3段（IQ の速さで動く）
int1 <= int1 + norm;
int2 <= int2 + int1;
int3 <= int3 + int2;

// 間引いた後、差分3段
wire signed [31:0] d1 = int3 - comb1_prev;
wire signed [31:0] d2 = d1   - comb2_prev;
wire signed [31:0] d3 = d2   - comb3_prev;
```

ステレオ副搬送波の位置（38kHz）を入れて漏れを測りました。

| | 38kHz の漏れ |
|---|---|
| 1次CIC（単純な移動平均） | -11.5dB |
| **3次CIC** | **-44.3dB** |

## ここからが本題：音が悪い

ここまでで音は出ました。しかし **雑音があり、プチプチというクリック音**が入ります。

ここから長く迷いました。振り返ると、迷った原因ははっきりしています。
**推測で直そうとしたから**です。「DC スパイクだろう」「クロックがずれているのだろう」と
当たりをつけて直しては、変化がなくて次の推測に移る。これを何度も繰り返しました。

以下は、測ってから分かったことです。

## 切り分け：原因はどちら側か

まず**原因がどちら側にあるか**を確定させます。録音済みのファイルを FIFO へ流すだけの
プログラム（`playraw.c`）を書きました。これで USB・`rtl_fm`・パイプという
リアルタイム要因を全て外せます。

| | ファイル再生 | リアルタイム受信 |
|---|---|---|
| プチプチ | **出ない** | 出る |
| 雑音 | 出る | 出る |

これで2つの症状が別問題だと確定しました。プチプチは供給側、雑音は受信・復調側です。
この切り分けを最初にやるべきでした。

## プチプチの原因

FIFO は 8192 段（約0.17秒）あります。残量を実測すると 2900〜5300 の間で振動していて、
**空にはなっていません**。つまり単純な供給不足ではない。

原因は2つとも PS 側のプログラムにありました。

### 1. スペクトル送信が常に空回りしていた

段8 で作った、FFT 結果をパソコンへ送る関数です。

```c
static void send_spectrum(void)
{
    for (int k = 0; k < NBIN; k++) {
        reg_write(REG_FBIN, k);
        int32_t re = reg_read(REG_FRE);   // ← 毎秒 1024 回のレジスタアクセス
        int32_t im = reg_read(REG_FIM);
        mag[k] = sqrtf(re*re + im*im);    // ← 毎秒 256 回の平方根
    }
    if (g_sock >= 0)                      // ← 判定がここ！
        sendto(...);
}
```

**送り先があるかの判定が関数の最後**にありました。パソコンの IP を指定していなくても
全ての計算が走ります。その間 FIFO への供給が止まる。冒頭で `return` するだけの修正です。

### 2. FIFO の状態を毎標本読んでいた

```c
while (reg_read(REG_STATUS) & ST_FULL) usleep(500);   // 毎標本
```

48828 回/秒 の AXI 読みは、それ自体が `rtl_fm` からの読み取りを圧迫します。
STATUS には残量が入っているので、一度読んで「あと何個書けるか」を覚えておき、
その分は状態を読まずに書くようにしました。

```c
static inline void fifo_put(uint32_t v)
{
    while (fifo_space <= 0) {
        uint32_t st = reg_read(REG_STATUS);
        fifo_space  = FIFO_DEPTH - ((st >> 16) & 0x3FFF) - MARGIN;
        if (fifo_space <= 0) usleep(200);
    }
    reg_write(REG_DATA, v);
    fifo_space--;
}
```

この2つでプチプチは消えました。

## 雑音の内訳を FFT で見る

録音した音声の周波数分布を取ったら、一目で分かりました。

| 帯域 | 実測 | 正体 |
|---|---|---|
| 0〜300Hz | **全パワーのほぼ全部** | 直流とドリフト |
| 18.5〜19.5kHz | 周囲より 12dB 高い | ステレオのパイロット信号 |

最大の成分が **0Hz（直流）** でした。11.9Hz が -6dB、60〜190Hz が -14〜-22dB。
FM 復調の出力には直流と超低周波のうねりが大きく乗ります。これがゴロゴロという雑音の正体です。

対策は2つのフィルタです。

**30Hz 高域通過**（1次）で直流と超低域を落とす:

```c
y = x - hp_x1 + ((int64_t)hp_y1 * HP_A >> 16);   // HP_A = a×65536 = 65283
```

**15kHz 低域通過**（63タップ FIR）で 19kHz パイロットを落とす。窓関数法（sinc × ハミング窓）で
設計し、係数を 32768 倍して整数化しました。実測の減衰量は 13kHz 0dB / 15kHz -6dB /
**19kHz -56dB** です。

## rtl_fm のオプションを実測で決める

ここも推測が通用しない部分でした。87.2MHz を 20 秒ずつ録音して比較します。

測り方に注意が要ります。最初「雑音／音声」の比で測ったのですが、**放送内容（音楽か喋りか）で
大きく振れて**使い物になりませんでした。そこで**音声が存在しない 20〜24kHz の絶対パワー**を
指標にしました。FM は振幅に依存しないので、この値はチューナーのゲイン設定に関係なく比較できます。

| 設定 | 雑音床 | 信号との差 |
|---|---|---|
| **`-g 30`** | **88.0dB** | **39.8dB** ← 最良 |
| `-g 20` | 88.5dB | 38.7dB |
| `-g 40` | 87.1dB | 36.2dB |
| ゲイン自動（既定） | 90.2dB | 33.6dB |
| `-g 49`（最大） | 92.9dB | 31.8dB |
| `-F 9` を付けた3通り | 91.8〜94.5dB | 33〜35dB |

分かったこと:

- **ゲインは自動にしない**。`-g 30` 固定で約 5dB 改善します。最大ゲインは最悪でした。
- **`-F 9`（high quality FIR）は使わない**。名前に反して雑音が 3〜6dB **増えました**。
- **`-s` は 244140（48828×5）**。195312 に狭めると逆に悪化しました。
  なお整数比であることは必須で、`-s 200k -r 48828` は 4.096 倍になり歪みます。

`-F 9` が逆効果というのは事前には予想できませんでした。測らなければ「高品質と書いてあるから」
という理由で付けたままにしていたはずです。

### デエンファシスは 50µs

FM 放送は送信時に高音を持ち上げてから送ります（プリエンファシス）。受信側で同じだけ
下げないとシャリついた音になります。

`rtl_fm -E deemp` はこれをやってくれますが、**時定数が 75µs（米国仕様）**です。
**日本は 50µs** なので、そのまま使うと高音を落としすぎてこもった音になります。
自前で掛けました。

```c
#define DEEMP_A 86        /* α×256、α = 1-exp(-1/(fs·τ))、τ=50µs */
deemp_y += (((int32_t)x - deemp_y) * DEEMP_A) >> 8;
```

これで「こもり」は解消しました。

## ここから先はソフトでは伸びない

フィルタもゲインも詰めましたが、雑音は残りました。掃引してみると理由が分かります。

| 周波数 | 雑音床との差 |
|---|---|
| **87.20 MHz** | **21.5dB** |
| 84.14 MHz | 8.3dB |
| 81.51 MHz | 7.0dB |

FM には**しきい値効果**があります。信号が雑音より十分（およそ 20dB）強ければ、
復調器は雑音をほぼ完全に抑え込みます。しかしそこを下回ると急激に雑音が増える。崖のような特性です。

21.5dB は、**その崖のふちに乗っている**状態です。音は出るが雑音も出る。30dB 以上ないと
「普通のラジオ」の音にはなりません。

付属の短い棒アンテナを水平にして窓際へ移してみました（日本の FM 放送は水平偏波なので、
垂直に立てていると偏波が 90度ずれます）。

| | 改善前 | 改善後 |
|---|---|---|
| 87.2MHz の強さ | 11.9dB | 13.3dB |
| 雑音床 | -9.6dB | -7.9dB |
| **差（SN）** | **21.5dB** | **21.3dB** |

**信号が 1.4dB 上がると同時に、雑音床も 1.7dB 上がりました。** 差は変わりません。
つまり雑音は外から来ていて、アンテナの感度を上げても信号と一緒に増える。
ここから改善するには指向性アンテナか、雑音源から離すしかありません
（KV260 本体そのものが疑わしい）。

## おまけ：RTL-SDR は偽の信号を出す

航空無線（118〜137MHz）とアマチュア無線（144MHz / 430MHz）も掃引してみました。

| バンド | 見つかった周波数 | 雑音床との差 |
|---|---|---|
| 航空無線 | 119.9933 MHz | 21.6dB |
| 航空無線 | 124.9978 MHz | 12.2dB |
| アマチュア 144MHz | なし | — |
| アマチュア 430MHz | 432.0020 MHz | 21.5dB |

一見受信できているようですが、**120.000 / 125.000 / 432.000 とキリのいい整数値**ばかりです。
これは受信機内部が出す偽の信号（スプリアス）の典型です。

確かめ方は簡単で、**時間変化を見ます**。本物の交信は出たり消えたりしますが、
内部スプリアスは常に一定です。120MHz 付近を 2分間、5秒おきに測りました。

```
差の 最小 6.8 dB / 最大 7.0 dB / 変動幅 0.2 dB
```

25回のスキャンで変動幅 0.2dB。完全に一定です。**偽の信号**でした。
さらに全体レベルが緩やかに下がっていて、これはドングルが温まってゲインが落ちたためです。
外部の電波ではないことの裏付けになります。

## 現状と未解決

正直に書くと、**PL で復調する版（`fmradio.c`）は、PS 側の `rtl_fm` を使う版より
まだ雑音が多い**です。シミュレーションでは振幅正規化も折り返し対策も効いているので、
原因は別にあります。判明している不整合:

- **CIC の出力スケーリングが間引き比 20 のまま**です。`d3 >>> 13` は CIC 利得
  R³ = 8000（間引き比20）を前提にしていますが、間引き比 5 では利得は 125 なので
  **64倍ずれています**。
- テストベンチも間引き比 20 のままで、RTL と食い違っています。

目標は gqrx と同等の音質ですが、まだそこには届いていません。次はこのスケーリングを直し、
テストベンチを合わせ、その上でステレオ復調（19kHz パイロットの PLL）に進む予定です。

## この記事で一番言いたかったこと

FPGA で信号処理を書くこと自体は、教科書通りにやれば動きます。難しいのはその先で、
**「なんとなく音が悪い」を「何がどれだけ悪い」に変換する**ところです。

今回、推測で直そうとした施策はほぼ全て空振りでした。当たったのは、

- ファイル再生と実時間受信を比べて症状を切り分けた
- 録音を FFT して雑音の帯域を特定した
- オプションを振って絶対値で比較した
- 時間変化を見てスプリアスを見破った

という、**測定してから動いた**ものだけです。しかも測り方自体を一度間違えて
（放送内容に左右される指標を使った）、そこもやり直しました。
