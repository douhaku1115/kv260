## はじめに

Xilinx Kria KV260 の PL（FPGA）から Pmod I2S2 で音を鳴らす記事の続きです。

- 段5（[前回](https://zenn.dev/)）で、PS→PL の AXI ストリーミングにより 28分の曲を
  丸ごと再生できるようになりました。
- この記事では、そこから **ステレオ化（段6）**、**PL でのリアルタイム音声加工（段7）**、
  **再生音のスペクトル可視化（段8）** まで進めます。

## 段6: ステレオ化

段5 までは左右同じ音（単音）でした。ステレオにするには、左右2つの標本を
どう PL に渡し、どう I2S の左右スロットに振り分けるかを決めます。

FIFO を32ビット幅にして、1段に左右をまとめて置きました（`[31:16]=左, [15:0]=右`）。
PS は左右2標本を1回の書き込みで送れます。

```verilog
// I2S 送出: LRCK(c[7]) の前半=左、後半=右
wire [SMP-1:0] cur = c[7] ? fx_r : fx_l;
```

```c
// play.c: 左右を1組にまとめて DATA へ1回で書く
uint32_t lr = ((uint32_t)(uint16_t)buf[2*i] << 16) | (uint16_t)buf[2*i+1];
reg_write(REG_DATA, lr);
```

### ハマり: 単音では片chの不具合に気づけない

ステレオにした直後、右chが鳴らずに悩みました。テスト音源（左だけ／右だけ）や
シミュレーションで切り分けた結果、**RTL は正しく右スロットにデータを出していました**。
原因は一時的なもので、左右同じ音を書けば両耳から鳴ることを確認して解決しました。

教訓として、段1〜5 が単音（左右同じ）だったため、**片chが鳴っていなくても
「鳴った」と判断できてしまっていた**こと。ステレオにして初めて左右の非対称が表に出ます。
左右で明らかに違うテスト音源を用意しておくと切り分けが速いです。

## 段7: PL でのリアルタイム音声加工（音量・エコー）

FIFO と I2S 送出の間に信号処理モジュール `audio_fx.v` を挟みました。

```
FIFO → [音量 ×GAIN] → [+ エコー(遅延0.25秒×ECHO)] → 16bit飽和 → I2S
                              ↑___ BRAMディレイライン ___|
```

- **音量**: `in * GAIN >> 6`（GAIN=64 で等倍）
- **エコー**: BRAM のディレイライン（約0.25秒）から遅延音を読み、フィードバックで
  混ぜる（リバーブ風）。書き戻すので減衰しながら繰り返す

レジスタを追加し（0x30 GAIN / 0x40 ECHO、いずれも 0x10 境界に整列）、
PS から `devmem` で再生中にリアルタイムで効き具合を変えられます。

```bash
sudo devmem 0xA0000040 32 0x80   # エコーを入れる
sudo devmem 0xA0000030 32 0x20   # 音量を半分に
```

### シミュレーションの罠: `x * 0 = x`

FFT ではなくこの段の話ですが、`audio_fx` を xsim で検証したとき、出力が全部 x に
なりました。原因は BRAM の未初期化値 x がエコーの乗算に入り、Verilog では
**`x * 0 = x`**（0 ではない）なので x が伝播したことでした。`mem` を initial で
0 初期化して解決しました（実機の初期ノイズ防止にもなります）。

## 段8: リアルタイムスペクトル表示

再生中の音を FFT して、周波数成分をパソコンにグラフ表示します。

```
KV260(play.c)                          パソコン(spectrum_view.py)
  左chを8192点FFT ─ UDP:50007 ─> 840ビン(0〜5kHz) ─> matplotlibで線グラフ
```

まずは手早く可視化するため、FFT は PS 側（`play.c`）で計算しました（反復 radix-2、
8192点、分解能 ≒ 48828/8192 ≒ 6Hz）。低域 840 ビン（0〜約5kHz）の振幅を
UDP でパソコンへ送り、パソコンの `spectrum_view.py`（matplotlib）が線グラフで描きます。

```python
# パソコン側: UDPで受けて線グラフを更新
data, _ = sock.recvfrom(8192)
vals = np.array(struct.unpack("%df" % NSEND, data))
line.set_ydata(vals)
```

### ハマりどころ

- **ポート衝突**: 最初 UDP 5005 を使ったら、Windows Media Player のサービス
  (`wmpnetwk`) が握っていて `bind` できず。50007 に変更して解決。
- **文字化けと軸**: matplotlib のデフォルトフォントは日本語非対応。`Meiryo` を
  指定。横軸はバンド番号ではなく実周波数[Hz]にすると数字とバー位置が一致する。
- **分解能**: 1024点では 763Hz/バンドと粗く、音程の変化が見えない。8192点に
  増やして約6Hz にすると、細かい周波数変化が追える。

## まとめ

- ステレオは FIFO を32ビットにして左右をまとめ、LRCK で振り分ける。
  単音の間は片chの不具合に気づけないので、左右別のテスト音源を用意する。
- 音量・エコーは FIFO と I2S の間に信号処理を挟み、`devmem` でリアルタイムに操作できる。
- スペクトルは FFT を PS 側で計算し、UDP でパソコンに送って matplotlib で描くのが速い。
  FFT を PL に載せれば KV260 単体で完結できる（今後の課題）。

## ソースコード

- `rtl/i2s_stream_axi.v` … AXI4-Lite + FIFO + ステレオ I2S 送出
- `rtl/audio_fx.v` … 音量・エコー（BRAMディレイライン）
- `sw/play.c` … 再生 + FFT + UDP 送信
- `sw/spectrum_view.py` … パソコン側のスペクトル表示

音声データ自体は第三者の録音由来のためリポジトリには含めていません。
`ffmpeg` の変換手順を載せてあるので、各自の音源で再現できます。
