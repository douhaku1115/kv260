## Step 1 — DisplayPortに何か映す

**目的**: 映像出力の経路を先に通しておく。ここが通らないと以降すべてが確認不能になる。

**やること**:
- Vivado でブロックデザインを作り、PL側にテストパターン生成（Video Test Pattern Generator IP でよい）を置く
- AXI4-Stream → Video Frame Buffer Write → DDR4、または PS DisplayPort の Live Video 入力へ直結
- KV260 は**アクセラレータ・アプリ方式**が標準。`.bit` + デバイスツリーオーバーレイを `/lib/firmware/xilinx/<app名>/` に置き、`xmutil loadapp <app名>` で読み込む。JTAGで焼くDE10-Nanoの作法とは違う

**解像度**: 最初から1920×1080を狙わない。**1280×720@60 または 640×480@60 で始める**。動いてから上げる。

**完了条件**: モニタにカラーバーが出る。

**詰まったら**: Xilinx の KV260 リファレンスデザイン（smartcam など）のブロックデザインを見る。ゼロから組むより速い。

## Step 2 — 万華鏡の折り返しを実装する（★ここが本番）

**目的**: 固定のテスト画像を入力に、万華鏡模様として出力する。**ピースも物理も無し。** ここだけで目標映像の「模様の構造」は完成する。

### 入力にするもの
512×512 RGB565 の静止画を1枚。PCで作ってKV260に置く。**内容は何でもよいが、模様の確認には色とりどりの図形が散らばった画像がよい**（`ref/target_*.jpg` の中心付近を切り出すのも手）。

置き場所は2案。**まず(a)で試す**:
- **(a) URAM/BRAM に載せる** — 512×512×16bit = 約4Mbit。K26のオンチップメモリに収まる。レイテンシが一定で確実
- (b) DDR4 に置いてAXIで読む — 1024×1024に上げたくなったらこちら。帯域は足りるがランダムアクセスのレイテンシ対策（キャッシュ/プリフェッチ）が要る

### 移植するもの
`ref/SCOPE_FS.glsl` を **Vitis HLS の C++ 関数**に書き直す。GLSLのfragment shaderは1ピクセル1呼び出しなので、HLSのパイプライン関数に素直に対応する。

処理の流れ（元コードの通り）:
```
1. 画面座標 → 視線方向 rd （ビュー行列を掛ける。傾き無しなら rd = (sx, sy, focal)）
2. slope = rd.xy / rd.z              断面で奥へ1cm進むごとの移動量
3. p = slope * Z_MIRROR              鏡の手前の端での位置
4. 三角形の外なら黒（筒の縁）を出力して終わり
5. dir = normalize(slope), remain = |slope| * (Z_CELL - Z_MIRROR)
6. ループ（下記）
7. 到達点 p / TUBE_R を [-1,1] とみなしてセル画像をサンプル
8. 反射回数 n で減光: color *= loss^n、合わせ目係数 seam を掛ける
9. 周辺減光 color *= 1 - 0.3*(sx²+sy²)
```

ループの中身（元コードは最大128回。**HLSでは 8〜16 回に固定して完全展開する**）:
```
鏡3枚それぞれと交差判定し、一番近い壁を選ぶ
  壁w: 法線 n_w（外向き）、位置 d_w
  進行方向との内積 dn = dot(dir, n_w)
  dn > 0 のとき t = (d_w - dot(p, n_w)) / dn
残り距離 remain 以内に壁が無ければ、p += dir*remain して終了
壁に当たったら:
  p += dir * t ; remain -= t
  2ミラーモードで底辺(wall[2])に当たったら黒にして終了
  三角形の3頂点への距離から seam を更新（合わせ目の黒い線）
  dir = reflect(dir, n_w)
  n++
```

### 固定小数点化
HLSでは `float` でも動くがリソースを食う。**まずfloatで動かし、映像が出てから `ap_fixed` に落とす**。逆順にやると原因の切り分けができなくなる。

### 鏡の三角形の作り方
`ref/mirrorGeometry.js` の通り。頂角 `180°/n`（n = ポイント数）の二等辺三角形、外接円半径 R=2.05。**これはピクセルごとに変わらない定数**なので、PSで計算してレジスタ経由でPLに渡す（AXI-Lite）。PLで三角関数を計算する必要は無い。

### 物理定数（cm）
```
TUBE_R   = 2.25    筒の内側の半径 = セル画像の半径
Z_MIRROR = 0.3     のぞき穴 → 鏡の手前の端
Z_CELL   = 12.2    のぞき穴 → セル手前層
CELL_GAP = 0.35    手前層 → 奥層
R(鏡の外接円) = 2.05
focal = 0.85 * zoom（zoom は 0.5〜2.5、既定1.0）
loss = 1 - 0.2 * fade（fade は 0〜1、既定0.4 → loss = 0.92）
```

**完了条件**: `ref/target_*.jpg` と**同じ構造の模様**（タイル状の無限反復、中心から外への減光、鏡の合わせ目の黒線）が静止画として出る。ピースの形が違うのは構わない。

## Step 4 — ピースを描く

**目的**: テスト画像をやめて、本物のセル画像を毎フレーム生成する。

**中身**: `ref/PART_FS.glsl` と `ref/PIECES_THEMES.js`。9種類のピース（色ガラス60・棒40・丸い塊20・三日月20・ビーズ40・天然石20・星20・ラメ400・気泡5、最大645個）を半径1の円内に描く。

**重要な構造**: セル画像は**2枚に分かれている**。
- 奥層（z<0.5）: 不透明。暗いオイル色の背景の上に描く
- 手前層（z≥0.5）: 透明度つき。合成時に奥層へ影を落とす

この2層合成をやらないと、**映像が平板になって「オイルの中に浮いている」感じが消える**。省略してはいけない。

**どこで描くか**: 645個の楕円/多角形のラスタライズ。**まずPS(Cortex-A53)で描いてDDR4に書き、PLはそれを読むだけにする**。4コアあるので512×512なら間に合う可能性が高い。間に合わなければPL側にラスタライザを作る。

背景のオイル色: 中心 RGB(0.055,0.045,0.08) → 外周 RGB(0.02,0.018,0.03) のグラデーション + ゆっくりした波。

**完了条件**: 目標映像とピースの形・色が一致する。

## Step 5 — 物理シミュレーション

**目的**: ピースがオイルの中で動く。

**中身**: `ref/stepSim.js`。**PS側で浮動小数点のまま実装してよい。** 645個の更新は4コアで余裕。

要点:
- 筒の回転速度と流体の速度の差 `wRel` が渦を生む
- 流体は粘度に応じて遅れて追従（`thin = 2.5^((0.5-viscosity)*2)`）
- 各ピースの目標速度 = 渦 + 対流（ラメは流されやすい 0.09、他 0.03）+ 沈降 + 微小ノイズ
- 速度は指数緩和で目標へ追従
- z方向はランダムウォーク（0.02〜0.98でクランプ）
- 押し合い: 円衝突を2回反復。z差0.45以上なら重なってよい
- 半径0.985の外に出たら内側へ戻す

**完了条件**: 回転を止めてもピースがゆっくり漂い、回すと渦を巻く。

## 付録D — カスタマイズ項目の全仕様

参照実装が持っている設定の全部。**FPGA版でどこまで可変にするかを決めるための仕様表。**
値は localStorage に保存され、次回起動時に復元される（`oil-kaleido-settings-v3`）。

### D-1. 鏡（模様の骨格を決める。最優先で可変にする）

| 項目 | 内部名 | 範囲 | 既定値 | FPGA実装での扱い |
|---|---|---|---|---|
| ミラーの枚数 | `mirror` | 3 または 2 | **3** | PLへ1bit。2のとき底辺の鏡を「黒い面」として扱う（反射させず打ち切り） |
| ポイント数 | `points` | 3〜12（整数） | **8** | 三角形の頂角 = 180°/points。**PSで三角形を計算しPLへ法線と頂点を渡す** |
| 模様の大きさ | `zoom` | 0.5〜2.5（0.05刻み） | **1.0** | `focal = 0.85 * zoom`。PLへ1値 |
| 遠くの暗さ | `fade` | 0〜1（0.01刻み） | **0.4** | `loss = 1 - 0.2*fade`。既定では loss=0.92。PLへ1値 |

**ポイント数を変えたときPSが計算してPLへ渡すもの**（`ref/mirrorGeometry.js` の通り）:
- 鏡3枚の外向き法線 `(nx, ny)` と法線方向の位置 `d` — 計9値
- 三角形の3頂点 `(x, y)` — 計6値
これらはフレーム内で変わらない定数。AXI-Liteレジスタで十分。

|---|---|---|---|---|

### D-5. 画質（PLのリソースと直結する重要項目）

| プリセット | `dpr` | 最大ピクセル数 | **反射回数上限 `refl`** | 内部反復 `iter` | 物体数 |
|---|---|---|---|---|---|
| 高 | 2 | 260万 | **64** | 28 | 56 |
| 標準（既定） | 1.5 | 160万 | **40** | 20 | 40 |
| 軽量 | 1 | 80万 | **20** | 12 | 24 |

**ここが移植の判断どころ**: WebGL版は標準でも反射を最大40回まで回す。
**HLSでは完全展開するので、この回数がそのままリソース量になる。**
`ref/target_*.jpg` を見れば分かるが、画面の大半は数回の反射で埋まっており、**8〜16回あれば実用上ほぼ違いが出ない**。
まず8回で作り、足りなければ増やす。64回を最初から狙わない。

（`iter` と `objects` は「中に入る」モード専用なので、この案件では無視してよい）

### D-6. 「中に入る」モード専用（**この案件では全部無視**）

`insideShape`（立体/平面）、`eyeHeight`（0.1〜10、既定1.0）、`insideSize`（0.05〜1、既定0.2）。
万華鏡の中に立って見回すモードの設定。**FPGA化の対象外。**

### D-7. 操作（設定ではなく動作）

| 操作 | 内容 |
|---|---|
| ドラッグ | 筒を回す（回転速度に反映される） |
| 傾ける | 視線の方向を変える（最大0.9rad）。指を離すと自動で正面に戻る |
| かき混ぜる | 全ピースに大きな初速を与える |
| 初期設定に戻す | 上の表の既定値に戻す |

**FPGA版での入力手段はユーザーに確認すること。** KV260にはタッチもマウスも標準では無い。
候補: ボタン（PL側GPIO）/ シリアルコンソール / ネットワーク経由（sshやHTTP） / 何も繋がず自動回転のみ。
**まず「自動回転のみ・操作なし」で作るのが最短。** Step 6で追加する。

### D-8. FPGA版で最初に固定してしまってよい値

Step 2〜4の間は、以下を**ハードコードして構わない**:
```
mirror = 3, points = 8, zoom = 1.0, fade = 0.4 (loss = 0.92)
theme = photo, viscosity = 0.5, autoRotate = 0.35
反射回数上限 = 8
ピース個数 = 上の既定値（合計266個）
```
これは `ref/target_8point_photo.jpg` と同じ条件なので、**出力を画像と直接見比べられる**。
可変にするのはStep 6でよい。
